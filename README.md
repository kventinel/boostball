# BOOSTBALL

A browser car-football game with adjustable teams (1×1 to 12×12), bots, multiplayer rooms, a ready-up lobby and post-match statistics. The interface is in Russian. The server runs on Node.js without third-party packages.

## Run

Requires Node.js 18+ and a browser with WebGL enabled.

```sh
git clone https://github.com/kventinel/boostball.git
cd boostball
npm start
```

Open [localhost:8080](http://localhost:8080). To accept connections from friends:

```sh
HOST=:: PORT=8080 npm start
```

Everyone must open the same server address. `HOST=::` listens on IPv6 and, where supported by the OS, IPv4. You can instead use `HOST=0.0.0.0` for IPv4 only. Remote access depends on the host's network configuration.

## Play with friends

1. Enter a nickname and select **С друзьями** (With friends).
2. Choose the team size and match duration, then create a room.
3. Share the six-character room code. Friends select **Войти по коду** (Join by code).
4. Everyone clicks **Я готов** (Ready). The creator stays in the lobby until they explicitly click **Начать матч** (Start match).
5. A shared three-second countdown starts the match. Bots fill unused seats.

The server freezes the clock and physics in the lobby. Readying up never starts a match automatically. If someone joins, that player must also confirm readiness. The host role passes to the next player when the creator leaves. After a match, the host can return everyone to the same lobby; names and the room code remain, while readiness and statistics reset.

Quick play is an offline match against bots. Joining a room that has already started is disabled.

## Controls

| Action | Key |
| --- | --- |
| Accelerate / reverse | W / S or Up / Down |
| Steer | A / D or Left / Right |
| Boost | Shift |
| Jump | Space |
| Follow / arena camera | C |
| Pause | Escape |

Touch controls appear on narrow screens. Pausing a network match only stops your own input; the shared match continues.

## Performance

- Static models stay in GPU buffers. Instanced rendering sends only per-car transforms each frame; browsers without the instancing extension use the same cached meshes with individual draws.
- Auto graphics targets 60 render frames per second and adjusts resolution if needed. High graphics allows up to 120 FPS; Light uses a lower resolution. Frame counters use elapsed wall time.
- Server physics uses a fixed 60 Hz step. Movement snapshots are sent at 20 Hz; names, roster and statistics travel on changes and once per second.
- Remote entities use a monotonic simulation-tick interpolation buffer with limited extrapolation. The local car predicts input immediately and smooths authoritative corrections.
- Input requests time out and retry, so a stalled request cannot indefinitely block further steering updates.
- Online clients and the server verify the room protocol. After upgrading a server, refresh open browser tabs.

## Statistics

The end-of-match table contains nicknames, teams, goals, assists, shots, touches, distance and top speed. Bots and departed players are marked. Own goals are shown separately. A qualifying deflection keeps credit with the original shooter.

An assist goes to the previous teammate who touched the ball, within ten seconds before the goal and without an intervening opponent touch. A shot is a new touch that sends the horizontal ball trajectory toward the goal mouth. Units are based on the game's simulation scale.

Rooms and results live in server memory and disappear on restart. Nicknames are display names, not authenticated accounts. This is a prototype; large-scale hosting, persistent accounts, saved matches and abuse controls are outside its current scope.

## Tests

```sh
npm test
```

Tests cover physics up to 12×12, scoring and assists, safe nickname display, lobby isolation, readiness, creator/guest permissions, host transfer, shared match start, final statistics, restart behavior, partial snapshots and prediction/interpolation under jitter. The tests require no package installation.

## Optional Linux user service

Clone the project to `~/repos/boostball`, then:

```sh
mkdir -p ~/.config/systemd/user
cp deploy/boostball.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now boostball
```

The service uses `/usr/bin/env node`; adjust `ExecStart` if Node.js is installed outside the service's PATH. To keep it running after logout, enable user lingering where allowed by your system policy.

Health check: `GET /health`. Logs: `journalctl --user -u boostball -f`.

## Assets

The arena, cars and ball are procedural WebGL geometry. The grass material is generated by a shader. No external image or game-engine downloads are needed. The interface optionally loads Barlow fonts from Google Fonts and falls back to system fonts when unavailable.
